# ADR 0003. Конфигурация

## Контекст

Системе нужны настройки модели, партии, лимитов и путей. Требования:
переключать модель без правки кода, ловить ошибки конфигурации при старте,
воспроизводить любой прогон.

## Решение

- **YAML-файл** `configs/settings.yaml` (в git) — основная конфигурация.
- **Переменные окружения** `CIV_*` (в т.ч. из `.env`, не в git) —
  переопределения поверх YAML. Вложенность через `__`:
  `CIV_LLM__ACTIVE_PROFILE=local_thinking`.
- **Выбор файла** — `CIV_CONFIG` (по умолчанию `configs/settings.yaml`):
  отдельный файл настроек под каждый эксперимент.
- **Порядок приоритета:** переменные окружения > YAML > значения по умолчанию.
- **Pydantic** (`pydantic-settings`): строгие типы, положительные числа,
  валидный URL.
- **`extra="forbid"`** во всех разделах: опечатка в имени поля — ошибка,
  а не молча проигнорированное значение.
- **Перекрёстные проверки:** активный профиль существует;
  `max_output_tokens` < `context_window`.
- **Профили моделей:** `local` (qwen3:4b-instruct) и `local_thinking`
  (qwen3:4b) — переключение одной переменной для сравнения моделей.
- **Явная передача настроек:** загружаются один раз при старте
  и передаются компонентам аргументом; глобального объекта нет.
- **Снимок настроек** (`save_snapshot`) сохраняется в папку каждого прогона.

## Детали реализации

- YAML читается загрузчиком и передаётся в `Settings` как аргументы;
  порядок источников развёрнут, чтобы переменные окружения были сильнее.
  Встроенный YAML-источник не используется: ему путь задаётся статически.
- `.env` загружается через `load_dotenv`, а не опцию `env_file`:
  с `extra="forbid"` встроенная загрузка отвергла бы `CIV_CONFIG`
  как неизвестное поле.
- Секретов в проекте нет (только локальная LLM). При появлении —
  только в `.env`, тип `SecretStr`.

## Альтернативы

| Вариант | Почему нет |
|---|---|
| Константы в коде | Изменение настроек требует правки кода, нет снимков |
| Только `.env` | Плоская структура, неудобно для вложенных профилей |
| Глобальный объект настроек | Тесты зависят друг от друга и от окружения |

## Последствия

- Любой прогон воспроизводим по его `config.yaml`.
- Конфигурации экспериментов для evals — отдельные YAML-файлы.
- Команды проекта запускаются из корня репозитория (пути относительные).
