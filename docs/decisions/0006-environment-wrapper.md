# ADR 0006. Обёртка над средой Freeciv

## Контекст

Агенты должны видеть состояние игры в компактном виде и отправлять только
допустимые действия. Разведка CivRealm (scripts/explore_*.py) показала:
- один `step()` — одно действие одного юнита/города; конец хода — `step(None)`;
- допустимые действия: `info['available_actions'][тип][id][имя] → bool`;
  типы: unit, city, tech, gov, dipl, player;
- наблюдение — словарь с картой 78×52 (массивы), игроками (115 полей),
  юнитами, городами, технологиями, дипломатией;
- `LLMWrapper` описывает окрестности юнитов (~930 токенов на юнит), но его
  `step` переводит имена **всех** действий, что ломает науку и правительство;
- CivRealm опрашивает сервер при импорте и падает, если тот не готов;
- проверка среды gymnasium даёт поток предупреждений: пространство
  наблюдений CivRealm объявлено неточно.

## Решение

Пакет `civ_agents.env`:

| Модуль | Назначение |
|---|---|
| `server.py` | Ожидание готовности сервера (`/pubstatus` → 200) до импорта CivRealm |
| `actions.py` | Внутренние имена ↔ читаемые; каталог допустимых действий; проверка |
| `state.py` | Свои типы состояния; извлечение из наблюдения |
| `neighborhood.py` | Окрестности из `LLMWrapper` → компактный текст |
| `summary.py` | Сводка хода по ролям с бюджетом токенов |
| `session.py` | Партия: запуск, действия, конец хода, горизонт, запись прогона |

- **Действия — в базовую среду** во внутреннем формате; `LLMWrapper` —
  только источник окрестностей (`get_llm_info`).
- **Источник правды о допустимости — `available_actions`.** Недопустимое
  действие не отправляется (защита от `E_BAD_COMMAND`, роняющего партию).
- **Читаемые имена для модели:** `move SouthWest`, `research Bronze Working`,
  `set rates science 60% luxury 0% tax 40%`. Каталог принимает читаемые,
  внутренние и короткие (`move SW`) имена, регистр не важен, id строкой.
- **Окрестности по клеткам, а не по юнитам**, компактным текстом:
  ~460 символов против ~2000 у `LLMWrapper` на клетку.
- **Сводка по ролям** (all, ruler, economist, military, science) с бюджетом
  токенов: разделы добавляются по приоритету роли, невместившиеся
  заменяются пометкой. Сводка всего хода — ~690 токенов (точно, по
  токенизатору модели); оценка по символам завышает на ~20%.
- **Длинные списки отфильтрованы:** наука — только доступное сейчас (а не 80
  целей), налоги — 3 типовых варианта из 36, анархия не предлагается.
- **Горизонт `max_turns`** контролирует сессия (ADR 0001).
- **Запись прогона:** `turns.jsonl` (состояние на начало хода),
  `actions.jsonl` (действия, принятые и отклонённые), `game_results.json`.
- Проверка среды gymnasium отключена (`disable_env_checker=True`).

## Находки на реальной игре

- Направления Freeciv: 0 СЗ, 1 С, 2 СВ, 3 З, 4 В, 5 ЮЗ, 6 Ю, 7 ЮВ
  (подтверждено: `hut enter 5` ведёт к деревне на юго-западе).
- **Повторная отправка текущего исследования сбрасывает накопленные колбы**
  (с повтором — 0/28 три хода подряд, без него — +1 за ход). Защита:
  текущая технология исключена из вариантов, а `GameSession.act` не
  отправляет повтор (`actions_skipped`).
- Результаты партии CivRealm подсчитывает при `close()`, поэтому сначала
  закрытие, потом `get_game_results()`.
- Второй поселенец не может основать город рядом с первым — каталог убирает
  `build city` сам.
- Открытый вопрос: поле `bulbs` города (3) не совпадает с приростом
  исследования игрока (+1 за ход).
- Открытый вопрос: что строит город (`production_kind`/`production_value`)
  пока не переведено в название.

## Smoke-тест

Модель `qwen3:4b-instruct` получила реальную сводку хода 1 (757 токенов
с системным промптом, 6,3 с) и ответила `unit 101: build city`:
поселенец на лугу у реки с пшеницей рядом — разумный выбор, формат соблюдён.

## Последствия

- Агенты работают с `TurnView` (состояние, каталог, окрестности, сводка)
  и не знают о CivRealm.
- Зависимость от внутреннего API CivRealm (`get_llm_info`) — в одном модуле.
- Тесты не требуют игры: поддельная среда и записанное наблюдение.
