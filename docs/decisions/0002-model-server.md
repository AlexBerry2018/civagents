# ADR 0002. Сервер модели и выбор LLM

## Контекст

По заданию нужна open-source LLM, локально. Железо: ноутбук с
RTX 3050 Laptop, 4 ГБ видеопамяти; около 1,3 ГБ из них занимает Windows.
Агентам нужен вызов инструментов (tool calling) и короткие ответы
в рамках бюджета времени на ход.

## Решение

- **Ollama** в Docker-контейнере (`compose.yaml`), версия `<версия>`.
- Модель **`qwen3:4b-instruct`** (Q4_K_M).
- **OpenAI-совместимый API** (`/v1`): один клиент на OpenAI SDK.
- Контекст 8192, KV-кэш `q8_0`, flash attention, один параллельный запрос.
- Размещение **20/80 CPU/GPU**: модель с кэшем контекста (~3,3 ГБ)
  не помещается целиком в свободную видеопамять.
- Порт открыт только на `127.0.0.1`, модели хранятся в volume.

## Рассмотренные альтернативы

| Вариант | Почему нет |
|---|---|
| llama.cpp server | Больше контроля, но ручная работа с моделями (GGUF, флаги) |
| vLLM | Рассчитан на серверные GPU с большим объёмом памяти, не для 4 ГБ |
| LM Studio | GUI-приложение, неудобно как зависимость проекта в Docker |
| `qwen3:4b` (thinking) | В 10+ раз медленнее на вызов: 16–21 с против ~1,5 с |
| Меньший контекст ради 100% GPU | Не хватит для состояния игры и описаний инструментов |
| `qwen3:1.7b` | Влезет целиком, но слабее; вариант на случай нехватки скорости |

## Находки

- Тег `qwen3:4b` в Ollama указывает на **Qwen3-4B-Thinking-2507**
  (digest `359d7dd4bcda`). Эта модель размышляет всегда: параметр
  `think: false` и `/no_think` не действуют.
- С thinking-моделью описание инструмента в промпте искажалось,
  модель путала имя функции с описанием и не возвращала `tool_calls`.
- С `qwen3:4b-instruct` вызов инструмента корректен и через родной API,
  и через `/v1` (`finish_reason: "tool_calls"`, аргументы — строка JSON).
- Ollama кэширует совпадающее начало промпта (`cached_tokens`):
  вызов с кэшем в 3–4 раза быстрее.

## Замеры

См. [`docs/benchmarks.md`](../benchmarks.md). Кратко:
- чтение промпта ~1160 ток/с, генерация ~15–18 ток/с;
- вызов с промптом 3,6–5,7k токенов: 8–10 с без кэша, 2–3,5 с с кэшем;
- загрузка модели ~25 с (холодный старт).

## Последствия

- **Бюджет хода:** вызов 3–10 с → при лимите 60 с на ход около 6–15 вызовов.
- **Короткие ответы:** каждый токен ответа ≈ 60 мс → JSON-действие без пояснений.
- **Компактная сводка состояния:** сырые данные игры дорогие
  (~2,2 символа на токен).
- **Порядок частей промпта:** неизменная часть первой для кэша. Гипотеза
  для проверки — ставить общее состояние хода первым, чтобы его
  переиспользовали все агенты в пределах хода.
- Адаптер должен вырезать блоки `<think>...</think>` и распознавать ответ
  без `tool_calls` как отдельный тип отказа.
