# ADR 0005. Журнал вызовов модели

Статус: принято
Дата: 2026-10-13

## Контекст

Нужно знать, что происходит с моделью во время партии: сколько вызовов,
времени и токенов уходит на ход и на каждого агента, какие ошибки случаются
и что модель ответила при неудаче. Это основа для отладки промптов,
evals и observability.

## Решение

Пакет `civ_agents.observability`:

| Модуль | Назначение |
|---|---|
| `context.py` | Контекст вызова (`turn`, `agent`) через `ContextVar` |
| `run.py` | Папка прогона `runs/<run_id>/` |
| `call_log.py` | Наблюдатель `CallLog`: запись каждого вызова в JSONL |
| `summary.py` | Сводка по журналу (CLI и функция) |

- **Подключение через наблюдатель** из ADR 0004: клиент модели не меняется.
- **Контекст вместо параметров:** ход и агент задаются блоком
  `call_context(...)` и попадают в журнал автоматически; клиент
  не знает об агентах. `ContextVar` корректен и при параллельной работе.
- **Папка на прогон:** снимок настроек, журнал, промпты, позже — результаты
  партии. `run_id` сортируется по времени, метка эксперимента в имени.
- **Формат JSONL:** запись дописывается в конец файла; при падении
  сохраняется всё записанное; файл читается построчно (jq, pandas, Loki).
- **Два файла:** `llm_calls.jsonl` (всегда, компактные метрики)
  и `llm_prompts.jsonl` (только при `logging.save_prompts`, полные сообщения
  и ответы), связаны `call_id`.
- **Неудачные вызовы журналируются с ответом модели:** для содержательных
  ошибок ответ берётся из исключения.
- **Сводка:** вызовы, ошибки по типам, повторы, токены и кэш,
  время (сумма, p50, p95), самый медленный вызов, разбивка по агентам.
  Перцентили — потому что среднее скрывает выбросы, а критерий приёмки
  ТЗ сформулирован через 95% ходов.

## Альтернативы

| Вариант | Почему нет (сейчас) |
|---|---|
| Обычный текстовый лог | Трудно агрегировать, нет структуры |
| SQLite | Лишняя зависимость для последовательной записи; JSONL проще читать внешними инструментами |
| Сразу OpenTelemetry + Langfuse | Больше инфраструктуры; будет на этапе observability, этот журнал станет одним из источников |

## Последствия

- Цикл игры и агенты оборачивают работу в `call_context(turn=..., agent=...)`.
- Каждая партия создаёт `Run` и сохраняет в него снимок настроек.
- `save_prompts` включается для отладки: файл промптов большой.
