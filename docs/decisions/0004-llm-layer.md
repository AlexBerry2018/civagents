# ADR 0004. Слой доступа к модели

## Контекст

Агентам нужно обращаться к LLM: отправлять диалог и описания инструментов,
получать текст или вызовы инструментов. Сервер — Ollama с OpenAI-совместимым
API (ADR 0002). Замеры и эксперименты показали, что сервер и модель ведут
себя неидеально:
- thinking-модели возвращают рассуждения в тексте, иногда только с закрывающим
  тегом `</think>`;
- модель может ответить текстом там, где ожидался вызов инструмента,
  без какой-либо ошибки API;
- Ollama молча обрезает промпт, если он длиннее контекста;
- холодная загрузка модели занимает 25–46 с;
- аргументы инструментов в OpenAI-формате приходят строкой JSON
  и могут быть некорректными.

## Решение

Отдельный пакет `civ_agents.llm`, через который идут все обращения к модели.

| Модуль | Назначение |
|---|---|
| `types.py` | Свои типы: `Message`, `ToolSpec`, `ToolCall`, `LLMResponse`, `Usage`, `FinishReason` |
| `errors.py` | Свои исключения в двух семействах |
| `base.py` | Интерфейс `LLMClient` (Protocol), запись `CallRecord`, тип `Observer` |
| `postprocess.py` | Чистые функции очистки ответа |
| `openai_compat.py` | Клиент для OpenAI-совместимого сервера на OpenAI SDK |
| `fake.py` | `FakeLLM` — скриптованные ответы для тестов и прогонов без GPU |
| `__main__.py` | Ручная проверка из командной строки |

### Свои типы и интерфейс
Остальная система не импортирует ничего из OpenAI SDK. Агенты принимают любой
объект с интерфейсом `LLMClient`: настоящий клиент или `FakeLLM`. Смена SDK
или сервера затрагивает один модуль; агенты тестируются без модели.

### Ошибки в двух семействах
- **Транспортные** (`LLMTimeout`, `LLMUnavailable`) — клиент повторяет сам.
- **Содержательные** (`LLMTruncated`, `LLMInvalidToolArguments`,
  `LLMNoToolCall`) — клиент не повторяет; исключение несёт исходный ответ,
  решение принимает цикл агента (переспросить или выбрать безопасное действие).
- **`LLMBadRequest`** (4xx) — ошибка конфигурации, без повторов.

Граница ответственности: клиент отвечает за связь, агент — за смысл ответа.
Повтор содержательной ошибки на уровне клиента дал бы тот же ответ
и потратил бюджет хода.

### Ретраи
- Свои, а не встроенные в SDK (`max_retries=0`): встроенные не знают о бюджете
  хода и наложились бы на свои.
- До 3 попыток, экспоненциальная задержка 0,5 → 1 → 2 с со случайным
  множителем 0,5–1 (jitter).
- Параметр `deadline`: таймаут запроса урезается до остатка времени; если
  остатка не хватает на ожидание перед повтором — ошибка сразу.

### Очистка ответа
- Вырезание `<think>...</think>`, ответа после одиночного `</think>`
  и оборванного `<think>`.
- Разбор аргументов инструментов в словарь; некорректный JSON или не-объект —
  `LLMInvalidToolArguments`.
- `finish_reason == length` важнее наличия вызова: обрезанный вызов
  не исполняется.
- Вызов инструмента определяется по наличию `tool_calls`.
- `require_tool=True`: ответ без вызова — `LLMNoToolCall`.
