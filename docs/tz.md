# Техническое задание: мультиагентный «правитель» Freeciv

## 1. Зачем это
Нужна система из нескольких LLM-агентов, которая сама играет во Freeciv (открытый аналог Civilization) за одну цивилизацию через CivRealm. Игра выбрана как полигон: у неё есть объективный результат (счёт, города, население, выживание), решения разного масштаба (стратегия на десятки ходов и ход отдельного юнита) и повторяемые партии. На этом полигоне проверяется, как устроить агентов, память, оценку и наблюдаемость при слабой локальной модели.

## 2. Цель и критерий успеха
- Сыграть заданное число ходов (по умолчанию 50) без падения партии.
- Набрать больше, чем случайный агент, на одинаковом горизонте; сравнить с одиночным агентом.
- Уложиться в бюджет времени на ход: **60 с** (не больше 10 вызовов модели на ход).
- В игру не должно попасть ни одного недопустимого действия: неверная команда в CivRealm роняет партию.

## 3. Ограничения
- Модель — **open-source, локальная**, без облачных API (Claude и другие закрытые модели не используются).
- Железо: ноутбук, RTX 3050 Laptop **4 ГБ видеопамяти**, Windows + WSL2. Отсюда — модель класса 4B.
- CivRealm требует Python 3.10 и старые зависимости (ray, setuptools<81, gymnasium<1.0).
- Работает один человек; срок — несколько дней.

## 4. Что система делает (функциональные требования)
1. **Подключается к игре:** ждёт готовности сервера, начинает партию, получает состояние и список допустимых действий на каждом шаге.
2. **Сжимает состояние** в короткую текстовую сводку для модели (свои города и юниты, окрестности, исследование, соседи) с бюджетом токенов; каждой роли — свой срез.
3. **Принимает решения ролями:**
   - *правитель* — стратегия и налоги (раз в 10 ходов);
   - *наука* — что исследовать (когда нужно выбрать);
   - *экономист* — поселенцы и рабочие, производство городов;
   - *военный* — разведка и оборона.
4. **Исполняет только допустимое:** исполнитель-код сверяет каждое предложенное действие со списком от игры; недопустимое отклоняется с причиной, ошибка возвращается модели для одного переспроса.
5. **Помнит:** события партии (новый город, потеря юнита, изученная технология), знания о правилах и стратегии из `.md`, уроки прошлых партий.
6. **Использует скиллы:** детерминированные процедуры (оценка места для города, порядок технологий, оценка угроз), результат которых подаётся модели подсказкой.
7. **Сохраняет всё о партии** в папку прогона: снимок настроек, состояния по ходам, действия, вызовы модели, события, алерты, итоговые метрики.
8. **Режимы для сравнения:** иерархия, один агент, случайный агент; отключение памяти и скиллов.

## 5. Нефункциональные требования
- **Надёжность:** сбой модели (таймаут, не-JSON, неверное действие) не роняет партию — советник пропускает ход; ретраи только транспортных ошибок с backoff.
- **Изоляция:** все компоненты в контейнерах; агент — не root, без capabilities, с лимитами памяти/CPU/процессов; порты только на localhost.
- **Наблюдаемость:** трейсы (ход → агент → вызов модели), метрики (время хода, вызовы и задержка модели, токены, действия, состояние партии), логи, алерты (долгий ход, ошибки модели, много недопустимых действий, агент завис).
- **Воспроизводимость:** зависимости по `uv.lock`, конфиг в `configs/settings.yaml` с переопределением через переменные окружения, снимок конфига в каждом прогоне.
- **Заменяемость модели:** слой LLM за интерфейсом (OpenAI-совместимый API); смена модели — правка профиля, не кода.
- **Тестируемость:** логика проверяется тестами без игры и без модели (поддельные LLM и среда).

## 6. Что не входит
- Дипломатия и переговоры с другими игроками всерьёз (только базовая оценка соседей).
- Поздняя игра (после ~90-го хода сервер сам завершает партию).
- Генерация и выполнение кода агентами.
- Обучение или дообучение модели.

## 7. Как проверяем (приёмка)
- Партия на N ходов проходит без падений, ни одно недопустимое действие не попало в игру.
- Evals уровня системы: random / single / hierarchy / без памяти / без скиллов — счёт, города, население, выживание, время и токены на ход, доля ошибок формата и недопустимых действий; несколько партий на вариант.
- Evals уровня модели: вопросы по правилам без памяти и с RAG, проверка кодом.
- В Grafana видны трейс хода, метрики, логи и правило алерта.
- Отчёт (`docs/report.md`) обосновывает выбор по каждому пункту задания и называет недостатки.
